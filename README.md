# Rosa - Сервис заказа бухгалтерских справок

## Технологический стек
* **UI:** C#, WPF, .NET
* **Архитектура и паттерны:** MVVM (CommunityToolkit.Mvvm), Dependency Injection
* **Работа с данными:** Entity Framework Core, SQLite
* **Логирование:** Serilog

## Инструкция по запуску
Приложение полностью соответствует критерию запуска без установки дополнительных компонент.
1. Склонируйте репозиторий на локальную машину.
2. Откройте решение `Rosa.sln` в вашей IDE (Visual Studio / Rider).
3. Назначьте проект `Rosa.UI` в качестве запускаемого (Startup Project).
4. Запустите приложение.
*Примечание: Локальная база данных SQLite (`requests.db`) будет автоматически создана в папке с исполняемым файлом при первом запуске приложения.*

## Описание функциональности

**Сценарии сотрудника:**
* Создание новой заявки (выбор типа справки, указание количества экземпляров, ввод опциональной причины).
* Отслеживание истории и статуса своих текущих и прошлых заявок.
* Динамическая смена пользователя: при вводе имени другого сотрудника история заявок обновляется автоматически.
* **Защита от дублей:** На уровне бизнес-логики и базы данных реализована проверка — сотрудник не может создать новую заявку на справку определенного типа, если предыдущая заявка такого же типа еще находится в работе (статус New или InProgress).

**Сценарии бухгалтера:**
* Просмотр общей очереди заявок от всех сотрудников в реальном времени.
* Просмотр деталей запроса (вид справки, количество, причина).
* Изменение статуса заявок с автоматическим сохранением изменений в базу данных.

## Ответы на вопросы для рефлексии

### 1. Какое архитектурное решение вы считаете самым рискованным и почему?
В рамках текущей реализации самым рискованным является использование двухуровневой архитектуры, при которой толстый клиент (WPF) напрямую обращается к базе данных SQLite. 
Для тестового стенда это приемлемо (удовлетворяет критерию отсутствия дополнительных компонент), но в реальной корпоративной среде это несет серьезные риски безопасности и масштабируемости.
Клиент не должен содержать строку подключения. Безопаснее использовать трехуровневую архитектуру, где WPF-клиент общается по HTTPS с защищенным Web API, который, управляет доступом к базе данных.

### 2. Где вы сознательно оставили технический долг? Как бы его закрыли при наличии времени?
* **Авторизация и идентификация:** Текущий пользователь просто вводится в текстовое поле. В реальном проекте необходимо интегрировать сервис аутентификации (например, Active Directory или JWT) и передавать контекст пользователя через Dependency Injection.
* **Отсутствие пагинации:** Сейчас метод получения всех заявок для бухгалтера выгружает данные целиком. При росте таблицы это приведет к падению производительности. Закрыл бы долг добавлением `Skip()` и `Take()` в репозиторий и реализацией постраничной навигации (или виртуализации) в DataGrid.
* **Миграции БД:** Используется `EnsureCreated()`, что подходит только для прототипов. В продакшене я бы настроил полноценные миграции Entity Framework для безопасного обновления схемы данных.

### 3. Что бы вы изменили, если бы знали, что сервис станет высоконагруженным?
* Перевел бы базу данных с SQLite на полноценную реляционную СУБД (например, PostgreSQL), чтобы обеспечить поддержку конкурентного доступа и высокую производительность транзакций.
* Вынес бы всю бизнес-логику в масштабируемые микросервисы (Web API) за балансировщиком нагрузки.
* Внедрил бы брокер сообщений (например, RabbitMQ). Заявки от сотрудников падали бы в очередь, а фоновые воркеры их бы обрабатывали. Это сняло бы нагрузку с основного API.
* Для мгновенного отображения статусов (без лишних запросов к БД) добавил бы кэширование на базе Redis.
